# MW-NV v1.0.0 — 작업 규칙

## 재개와 범위

- 먼저 `STATE.md`, `DECISIONS.md`, `git status --short`를 확인한다.
- 원본 `CODEX_EXECUTION_PLAN.md`에서는 A절과 현재 Cxx 카드만 읽는다.
  `rg -n '^#### C[0-9][0-9]\.' CODEX_EXECUTION_PLAN.md`로 찾는다.
- 원본과 충돌하면 사용자가 확정한 `DECISIONS.md`가 우선한다.
  원본 첨부 운영 규칙은 `reference/AGENTS.original.md`에 보존했다.
- 한 번에 Cxx 하나만 구현한다. 완료 조건 통과 후 다음 기능을 선행하지 않는다.
- 구현 파일은 최대 3개를 권장한다(테스트·설정·문서 제외).
- 작업은 `v1.0.0/` 아래에 둔다. 다른 버전·기존 사용자 변경을 보존한다.
- 기존 체크아웃을 사용한다. 명시적 요청 없이 worktree를 만들지 않는다.

## 아키텍처

- HQ는 팀별 읽기 전용 관측을 받아 허용된 게임 명령만 반환한다.
- 결정론적 엔진만 이동·충돌·탐지·추상 전투·점령·수송·보급·점수를 처리한다.
- 유닛별·물리 tick별 LLM 호출은 금지한다. 규칙 HQ만으로도 게임이 동작해야 한다.
- 양팀 로컬 LLM HQ는 필수 연동이며, 실패 시 규칙 HQ로 복구한다.
- 차량은 전부 무장 없는 수송 전용이다. 수치는 원본 D–G절을 따른다.
- 게임 에이전트는 허용된 opcode만 생성한다. OS 명령·임의 코드 실행을 제공하지 않는다.

## 검증과 기록

- 변경과 직접 관련된 테스트를 실행한다. 미실행 검사를 통과로 보고하지 않는다.
- 같은 실패 명령을 수정·새 진단 없이 반복하지 않는다.
- 새 의존성은 해당 단계에서만 도입하고 잠금 파일을 갱신한다.
  사용자는 계획에 필요한 오픈소스 조사·설치를 승인했다. 유료 서비스는 사용하지 않는다.
- `dev/v1.0.0`에서 작업하고 완료 시 테스트 → `STATE.md` 갱신 → 커밋 → push한다.
- 중단은 WIP 커밋으로 보존한다. 테스트 실패와 push 실패는 구분해 기록한다.
- 주요 단계에서 PR을 만들고 검증 결과를 적는다. 승인 없이 main을 강제 갱신하지 않는다.
- 비밀값·가상환경·모델·대형 로그는 Git에 넣지 않는다.
- `STATE.md`는 15줄 이내: 작업 ID, 상태, 변경 경로, 실제 테스트 결과,
  blocker, 다음 작업·실행 명령, 사용량(확인 불가 시 UNKNOWN).
- 최종 보고는 완료 작업·테스트·커밋/push·남은 문제·다음 Cxx만 간단히 쓴다.
- 자동 실행 일정은 만들지 않는다. 사용량·계정 한도를 추정하지 않는다.
