# 수송 교통 수정

규칙 버전 `combined-arms-2`, 카탈로그 `combined-arms-1`.

## 변경

- 차량 ID·실제 HQ 방향에 따라 거점 주변 하차/화력 배치 지점을 분산한다.
- 관측된 아군 위치와 활성 이동 목적지를 피하고, 지형·차량 발판 크기를 검사한다.
- 하차를 마친 빈 차량은 높은 우선순위로 거점 바깥 주차 지점으로 이동한다.
- 동적 장애물로 경로가 막히면 정적 경로를 유지하고 정지·주기적 재탐색한다.
- 낮은 ID 차량에 통행 우선권을 주고, 다른 차량은 합법적인 측면 공간으로 양보한다.
- 대기 중 이동 거리/연료를 소비하지 않으며 60초간 진전이 없으면 TRAFFIC_TIMEOUT으로 작업을 반환한다.
- 승차는 차량별 분대 FIFO와 간격 있는 개별 대기 위치를 사용한다. 한 명씩 500ms에 탑승한다.
- 선두가 탑승할 때 남은 병사의 이전 접근 경로를 버려 새 대기 위치로 재계획한다.
- 10개 최근 명령 외에도 활성 명령은 관측에 계속 남겨 긴 승차 예약이 사라지지 않게 한다.
- 수송/승차 작업 TTL은600초로 늘리고, 연료0인 차량에 이동 명령을 반복하지 않는다.
- 헬기는 엔진 차원에서 양팀 착륙 지점을 예약한다. 충돌 예약에는 근처 합법 지점을 택한다.
  기존의 지형/정지 차량 위 불법 착륙 거부는 유지한다.

## 검증

검사 파일 `tests/test_traffic.py`:
분산 슬롯·활성 목적지 예약, 좁은 통로 대기/연료 보존/장애물 해제 후 재개,
두 분대 FIFO 승차, 긴 명령 기록에서 예약 보존, 양팀 헬기의 같은 좌표 접근 후 분리 착륙, 실제 HQ 방향에 따른 슬롯 반전.
기존 수송·경로·리플레이·관측·HQ 회귀 검사도 실행한다.

10경기 재검사는 기존 seed0–4×기본/좌우반전, 동일 알고리즘 HQ와0.2초 tick이다.
미술은 엔진 상태와 난수를 바꾸지 않는다. 결과와 제한은 COMPARISON.md에 기록한다.

## 호환성

이전 engine replay는 변경된 규칙으로 실행하지 않으며 버전 오류로 거부한다.
기존 화면용 replay 재생은 유지한다. 기존 NumPy 정책은 새 규칙에 재학습해야 하며,
호환되지 않는 정책은 알고리즘 HQ로 복구한다. 이전 전적도 규칙별로 구분한다.
완벽한 교통 해소를 가정하지 않으며 적의 봉쇄·정원·연료·지형 제약은 여전히 존재한다.
