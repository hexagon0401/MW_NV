# 픽셀 미술·수송 수정 후 10경기 분석

## 실행 조건

기존 검사와 같은 seed 0–4를 기본/좌우 교대하여 각각 실행했다. 양팀은 동일 TacticalHQ 알고리즘이며 LLM·PPO를 호출하지 않았다. 물리 tick은 0.2초 그대로 두고 실제 시간 대기만 제거했다. 규칙은 combined-arms-1 → combined-arms-2, 카탈로그는 combined-arms-1이다. 수송 규칙과 후보 지점이 달라져 전투 전개도 달라지므로 이 결과를 순수 성능 벤치마크나 학습 성능 향상으로 해석하지 않는다.

수정 후 10/10경기 정상 종료. 시뮬레이션 231.5분을 실제 257.322초에 실행했다(약 53.98배속). 최종 상태의 범위/음수 HP/탑승자 연결/정원/중복 탑승 검사 0건, 명령 제출 거부 0건이다. 이는 전체 tick의 모든 충돌이나 모든 시스템 오류 부재를 증명하지 않는다.

## 해석과 남은 문제

1. **차량 경로 실패 감소:** 동적 장애물을 영구 지형 장애로 취급해 즉시 실패하던 문제를 대기·재탐색·합법 측면 양보로 바꿨다. 하차 후 외곽 주차와 목적지 예약도 추가했다. 단순히 실패 이름만 바꾼 것은 아니며 실제 탑승·하차가 늘었다. 그러나 대기 시간 초과 253건이 남아 혼잡 교차로·적 봉쇄에 대한 완전한 교통 해결로 볼 수 없다.
2. **보병 길막이 다음 우선 대상:** 전체 BLOCKED는 577→923건으로 오히려 증가했다. 수정 후 점령 이동 748건, 일반 이동 148건이 대부분이다. 수송이 전방에 더 많은 보병을 데려간 뒤 분대 집결/점령 접근에서 혼잡이 드러났다. 다음 수정은 점령 반경 안의 분산 도착과 보병 국소 재탐색이어야 한다.
3. **진영 균형 미해결:** A6승/B4승이지만 시작 위치로 보면 왼쪽9승/오른쪽1승이다(이전 왼쪽4승). 팀 문자 기준 배치 편향을 제거하고 실제 HQ 방향으로 슬롯을 반전했어도 결과는 편향됐다. 지도 통로·시설 접근, 고정 실행 순서, 후보 경로/교통의 영향을 분리 진단해야 한다. 5개 seed만으로 원인을 단정하거나 밸런스가 좋아졌다고 주장하지 않는다.
4. **헬기 예약 효과와 한계:** 서로 같은 좌표를 예약하던 착륙 충돌에 우회 착륙을 추가했다. LANDING_INVALID는30→1건이다. 움직이는 차량의 도착지 진입 등은 여전히 최종 착륙 검사가 필요하다.
5. **보급/전투 변화:** NO_FUEL6건, ILLEGAL_STATE71건, EXPIRED46건이 남았다. 포격은303→91회로 감소했다. 경기 단축·교전 위치 변화가 함께 발생했으므로 포격 AI가 좋아졌다는 근거가 아니며 별도 검토가 필요하다. 정지한 생존 유닛 목록은 의도적인 지원 대기와 실제 정체를 구분하지 못해 고장 수로 사용하지 않는다.

## 미술·인터페이스 검증

- 보병/실차 모티브 차량을 정수 픽셀·군집 명암·디더링·nearest 확대 방식으로 재작성했다. 나무는 불규칙 수관과 덩어리 명암을 사용한다. UI 색상·폰트는 유지한다.
- Chromium: 128보병+20차량을 배치한 렌더 장면, 실경기 초기 병력 수, 양팀 패널, 유닛 hover meter, 모바일 접이식 패널, 경기 종료 전적 갱신 검사 통과. 이 장면의 위치는 렌더 검사 용도로 밀집 재배치되었다.
- 최종 software GPU(SwiftShader) 측정7FPS. 기능 검사 통과와 부드러운 성능은 구분하며, Intel Mac 하드웨어 가속 성능은 미검증이다.
- Python124개 / JS11개 테스트 통과, production build 통과. 새 수송 검사는 분산 슬롯·경로 대기/연료 보존/재개·분대 FIFO·활성 예약 유지·헬기 분리 착륙·실제 HQ 방향 대칭을 확인한다.
- 구형 화면 리플레이는 유지한다. 이전 규칙의 엔진 재실행/NumPy 정책은 버전 불일치로 거부/알고리즘 복구하며 재학습이 필요하다.
