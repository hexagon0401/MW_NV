# 학습 현황·고속 실행·맵 전이 준비

## 구현

- 공개 사이트 상단은 `/api/training`에서 30초마다 보고를 읽는다. 회차, 완료된 전체 학습 스텝, 현재 정책 누적 스텝, 시뮬레이션 배속, CPU/PPO, 지형 변형, NIM 미사용, 보고 시각을 표시한다. 연결 불가와 3분 이상 지난 보고를 구분한다. 이는 엔진 라이브 관전이 아닌 학습 상태 보고다.
- 진행 보고는 비공개 Storage의 작은 JSON 하나를 교체한다. 비밀키/호스트 경로는 보고에 넣지 않는다. 서버 키는 Pages에만 둔다.
- 학습은 실제 시간 sleep 없이 30초 시뮬레이션 단위로 진행한다. 물리 tick0.2초는 유지한다. 배속은 실제 처리한 시뮬레이션 시간/벽시계 시간으로 계산한다. 리플레이는 원래 tick을 유지해 기본1배속이며 사용자가 속도를 바꿀 수 있다.
- 완료된 학습 경기만 gzip·read-back SHA256 검증 후 `training-latest`에 덮어쓴다. manifest도 동일 ID 하나를 교체해 재연결 중복/스토리지 증가를 제한한다. 기존 수동 업로드 경기는 보존한다. 경기 종료 이후에만 업로드하므로 현재 학습 정책은 경기 도중 PPO 업데이트에 따라 변할 수 있으며 고정 정책 평가 경기와 구분해야 한다.
- **핵심 수정:** 이전 반복기는 매 라운드 정책을 새로 생성하고 직전 정책을 상대편으로만 사용했다. 이제 `.zip`으로 가중치·옵티마이저·스텝 수를 로드해 이어 학습한다. 전적에 기록하는 신규 스텝과 정책 누적 스텝을 분리해 중복 합산을 막는다.
- 상대는 알고리즘, 직전 정책, 이전 정책을 순환한다. 정책 자동 승격은 유지하지 않는다. 체크포인트는 최근8개와100회 단위 기념점을 보존한다. 재개 번호는 남아 있는 최대 번호 이후이며 전체 학습량은 state.json에 보존한다.

## 다른 맵을 위한 준비와 제한

학습 seed0–49, 보류 seed10000–10099 분리를 유지한다. 훈련 지형은 기본/상하 반전/숲을 성기게 변경/두 변형 조합의4종이다. 지형 변형 RNG는 엔진 RNG와 분리하고 시설·분대·차량·보병을 함께 변환한다. 병력과 주요 도로 구조는 보존한다. **4개의 완전히 새로운 맵을 만들었다는 의미가 아니다.**

CandidateEnv는 `scenario_factory(seed,swap)`를 주입받는다. 새 맵은 이 함수에서 같은 규칙·카탈로그를 가진 합법 WorldState를 반환하면 연결할 수 있다. 입력 크기1056/행동65와 지도 크기에 대한 좌표 정규화를 유지해 모델을 맵의 특정 unit ID와 직접 결합하지 않는다. 맵이 바뀌어도 무조건 잘한다는 보장은 없다. 현재 전역 소유권 요약은 처음3개 거점만 포함하므로 더 많은 거점/새 규칙/새 무장은 계약 확장과 추가 검증이 필요하다. 정책 후보에는 실제 시설/부대를 연결하되 허용 관측만 사용한다.

`learning.candidate_evaluate --terrain-variants`는 변형 맵 보류 평가 경로다. 변경 전 정책 round000008을 seed10001 상하반전 맵에서 양팀으로 평가한 기준값은 **0승2패**다(A4:B103, A100:B12; 정책이 각각 A/B). 작은 표본이며 변형도 훈련과 같은 계열이다. 수정된 정책의 전략 개선이나 완전히 다른 맵의 전이 성공으로 해석하지 않는다. 원자료 `baseline-transfer.json`.

## 검증

- 지형 변형 결정론·128명/20대·시작 위치 통행 가능, 외부 scenario factory 고정 관측 계약 검사.
- 실제64+64스텝 학습에서 정책 누적128 및 저장/재로드/NumPy 추론 일치 확인.
- 현 프로세스도 round000008의256스텝 정책을 이어받아 round000009의512스텝 체크포인트 저장을 확인했다. 이전 독립 라운드들의 전체 작업량과 정책 실제 누적 학습량은 다르다.
- Python 학습/전술9개 + 보존 검사1개 통과. JS15개, production 및 Functions 빌드 통과.
- 공개 `/api/training`200의 실제 보고와 목록의 training-latest를 확인했다. Chromium 로컬 실행에서 실제 학습 보고를 읽어 상태줄·1배속·데스크톱/390px 모바일 전장 크기를 검사했다. screenshot desktop.png/mobile.png. 원격 Chromium은 프록시 CA 오류가 있어 검증을 우회하지 않고 로컬 브라우저 검사와 검증된 Python TLS 원격 API 검사로 나누었다.

## 운영

현재 Codex 환경에서 CPU PPO를 계속 실행한다. 환경 종료 시 중단될 수 있다. 모델·DB·대형 리플레이·키는 Git에 넣지 않는다. 재개 전에 같은 프로세스가 실행 중인지 확인하고 중복 실행하지 않는다.

```bash
MW_NV_PUBLISH_TRAINING=1 OMP_NUM_THREADS=2 MPLCONFIGDIR=/workspace/.cache/mpl \
.venv/bin/python -u -m learning.continuous --root data/nim-approved-training --rounds 0 --steps 256
```

로그 runner-v2.log, PID runner.pid, 최신 상태 state.json/training-status.json. 학습중 NIM은 호출하지 않는다. 상단 속도는 업로드/학습을 포함한 벽시계 기준이며 하드웨어와 교전량에 따라 변한다. 사용량 UNKNOWN.
