# 선점령·승패 통계

목적: 중앙·북부·남부 선점과 최종 승패의 관계를 나중에 검증할 수 있도록 완료 경기 원장에 자료를 쌓는다. 빈도/승률은 상관관계이며 인과 효과나 강화학습의 발견 자체를 증명하지 않는다.

## 기록

각 match 레코드의 objective_stats(schema1)에 거점별 최초 점령 팀·시각, 최초 소유 상실(중립화 포함), 상대의 실제 재점령, 최초 팀의 회복, 점령 횟수, 전체/최초 연속 보유 시간, 최종 소유 팀을 기록한다. 최초 점령 팀은 재점령으로 덮어쓰지 않는다. 북201/중앙202/남203이며 다른 ID는 임의 방향을 붙이지 않고 거점ID로 표시한다.

최초 점령 당시 점수와 생존 보병/차량 규모,180/300/600/900초 소유 상태, 전체 경기의 첫 점령 장소와 각 팀의 첫 점령 완료 장소도 기록한다. 같은 tick의 여러 점령에는 순서 우열을 부여하지 않는다. 아직 도달하지 않은 시점은 not_reached, 초기부터 소유하던 거점은 선점 경쟁 제외로 구분한다. 시각은 리플레이와 같이 (event.sim_tick+1)*tick_s다.

원본 World 이벤트/RNG/보상/규칙을 변경하지 않는다. 실제 tick0 초기 snapshot과 전체 이벤트를 가진 새 완료 경기에서만 수집한다. 예전 원장처럼 정보가 없으면 missing으로 집계하며, 최종 소유나 승패로 최초 점령을 추측하지 않는다. SQLite/기존 JSONL 내보내기·가져오기와 checkpoint DB 복사에 함께 보존된다.

## 집계와 조회

GET /api/objectives는 다음을 반환한다.

- 거점별 선점 팀 최종 승/패/무·표본 수·승률(승/표본, 무 포함).
- 선점 뒤 보유를 잃은 경우와 상대가 실제 재점령한 경우 각각의 최종 승률.
- 최초 팀이 다시 회복한 경우, 보유 시간·점령 속도·종료 점수 차.
- 북+중/중+남/북+남/세 거점을 같은 팀이 먼저 확보한 경우.
- 전체 최초 점령 장소, 각 팀의 첫 점령 완료 장소와 승률. 첫 목표 의도를 추측한 지표가 아니다.
- 최초 점령 직전의 점수·보병·차량 차이와 원장 정보의 수집률.

mode/rules_version/catalog_version/map_id/map_version/map_family/swapped/policy_a/policy_b로 조건을 좁힐 수 있다. 서로 다른 정책·맵·진영과 원래 점수/병력 우세를 섞은 전체 승률만으로 선점의 효과를 단정하지 않는다. 누적 자료가 적으면 실제 판단을 보류한다.

로컬은 SQLite에서 읽고, Pages는 비공개 Storage의 압축 cohort 집계를 서버에서 읽는다. 키를 프런트엔드로 보내지 않는다. 집계는 기존30초 보고 경로로 게시한다. 사이트 상단 ‘거점 선점 분석’에서 필터·표·조합을 조회한다.

## 검증

Python14개(거점 수집·필터·보유/상실/회복·동시 점령·누락·원장/JSONL·순수성·API 포함), JavaScript24개, production build 통과. 추가로 기존 training enhancement 관련 검사를 포함한17개도 통과했다. Chromium의 desktop/mobile 필터·횡스크롤·Escape는 명시적인 fixture로 검사했다. desktop-fixture.png/mobile-fixture.png는 실제 누적 승률이 아니다.

향후 전체 학습 교정·GitHub 정책 이관·전술 발견 검증은 docs/learning-repair-plan.md에 정리돼 있으며 이번 거점 통계 구현이 그 전체 계획 완료를 뜻하지 않는다.

## 실제 적용 확인 — 2026-10-26 KST

정식 배포 aea6b716, 사이트 https://mw-nv.pages.dev. 공개 /api/objectives HTTP200과 원격 Chromium 표/필터 진입 및 pageerror0을 확인했다. 실제 학습 완료 경기의 최초 점령 팀·소유 상실·최종 소유가 SQLite에 기록됐으며, 공개 집계에도 새 자료1경기가 반영된 것을 확인했다(production.json/deployed.png). 이는 기능 동작 증거이며 선점 효과에 대한 충분한 통계 표본이 아니다.

원장에는 기존 경기의 선점 정보를 추정해 채우지 않았다. 수집률의 '과거 정보 없음'에 남아 있으며 새로 완료되는 경기부터 증가한다. 학습은 안전 checkpoint에서 그대로 재개했고 가중치/optimizer/보상/엔진 규칙은 변경하지 않았다. 확인 시 generation1876,681경기,120064스텝까지 이어졌다.
