# T07 학습 교정·통계·정책 보존·전술 발견 추적 계획

상태: 부분 구현. T09에서 독립 PPO·공정 배정·아카이브·행동 지문·사건 순서·관전 통계를 구현했다. 실제 동작/검증은 docs/league-transition/README.md 참조. 아래 전체 계획이 완료된 것은 아니며, 전술 개입 인과 비교·공유 PPO 대조 실험·추가 교통 교정은 남아 있다.
확정: 정책10경기·전체복구50경기 누적 GitHub 보관, 통계 파일+사이트, 비용 서비스 추가 없음.

## 1. 기존 수정 범위

- SQLite 기존 기록을 유지하고 경기 조건/학습 정책 역할/세대·스텝 구간/명령·전술·자원·전투·교통 통계를 추가한다. 과거에 없는 정보는 누락으로 표시한다. 종료·재시작·가져오기 고유 ID로 중복을 막는다.
- 승률은 학습 정책 기준 최근50/100경기, 고정 평가, 팀·위치·맵·상대별로 분리한다. 통계는 엔진 이벤트를 읽으며 게임 RNG/물리를 바꾸지 않는다. 중간 집계도 checkpoint에 보존한다.
- 10개 완료 학습 경기마다 정책과 통계 구간,50개마다 전체 복구본을 불변 GitHub Release 자산으로 보관한다. 평가할 정확한 정책도 시작 전에 고정한다. 작은 인덱스만 training/checkpoints 브랜치에 커밋한다.
- 업로드→재다운로드→SHA256/로딩·격리 복구 검사→인덱스 기록이 끝나야 이관 완료로 처리한다. 과거 원격 자산과 미전송 파일을 지우지 않는다. 월별 Release를 자산250개 단위로 나눈다.
- 로컬은 최근 복구본2개·상대8개·기준정책·평가 우수3개를 유지한다. 대기 파일2GiB 또는 디스크 여유1GiB 한도에 닿으면 안전 업데이트 경계에서 학습을 대기시킨다. 누락을 감추며 삭제하지 않는다.
- 16경기 블록의 A/B×서/동4조합 각각에 기준2·과거1·알고리즘1을 배정하고 순서를 별도 seeded 순열로 정한다. 블록·상대·맵·순서와 RNG를 저장해 재개한다.
- 리더 점 대신 살아 있는 분대원 전체 오프셋이 통과하는 경로와 목표 슬롯을 검사한다. 수리/보급은 합법 접근→정지→거리검사→작업으로 처리하며 차량 상호작용은 차체 간 거리로 판정한다. 차량 양보에서 고정 낮은 ID 우선 편향을 제거하고 예약·우회·대기를 제한한다.
- 보상/학습률/모방 가중치는 우선 유지해 실행 오류 수정과 파라미터 튜닝을 섞지 않는다. 규칙4 새 실험으로 actor만 명시적 이관하고 critic/optimizer/buffer는 초기화한다. 관측·행동 차원과 catalog/map는 유지하고 이전 규칙 전적은 분리한다.
- 개발 평가:50경기마다5개 보류 seed×학습 팀2×시작 위치2=20경기. 별도 확인:250경기마다 해당 구간 우수 후보 하나를 추가20개 seed×4조합으로 검증한다. 자동 정책 승격은 하지 않는다. NIM 참여 점검은 별도 분류하고 fallback을 기록한다.

## 2. 무엇을 학습으로 얻었는지 확인하는 추가 체계

### 2.1 행동 지문과 선택 기회

정책별 전술 선택을 비교 가능한 수치 묶음(행동 지문)으로 기록한다.

- 점령/방어/정찰/수송/대장갑/포격/보급/치료/수리/후퇴의 제안 기회·선택·접수·완료·실패 횟수.
- 선택률은 해당 후보가 실제 가능했던 기회를 분모로 사용한다. 전장 상황 때문에 포격 기회가 늘어난 것을 학습 변화로 오인하지 않는다.
- 초반0–300초/중반300–900초/후반900초 이후의 선택 비중·첫 점령 시간·거점 유지·병력 손실 가치·자원 소비/성과.
- 보고서는 실행·규칙·관측계약·후보 생성기·맵/변형·상대·팀·시작 위치·자원/초기 편성을 함께 기록한다.
- 학습 경기의 정책 시작/종료 버전 범위와 고정 평가 정책을 구분한다. 조건이 다른 실행을 자동으로 '학습 전후'로 묶지 않는다.
- actor 업데이트 수나 모방 손실 감소는 전술 향상의 증거로 대체하지 않는다.

### 2.2 전술 순서 감지기

첫 버전은 다음 네 가지를 코드로 정의하고 detector_version과 시간/거리 조건을 결과에 기록한다. 이름은 관측된 사건 순서를 설명하며 승리 원인을 단정하지 않는다.

1. 하차 후60초 안에 같은 분대가 거점 점령에 실제 참여.
2. 거점 주변 포격 후60초 안에 해당 팀이 그 거점을 점령.
3. 자기 거점 방어 지시 후60초 이상 소유 유지.
4. 수리된 차량이 이후60초 이상 생존하고 전투/수송을 재개.

점령 참여자·수리 대상·이벤트 시각 등 필요한 증거를 새 통계에서 명시적으로 수집한다. 참여자를 확인할 수 없는 구형 기록에서는 같은 팀 사건만 보고 같은 분대의 전술이라고 추측하지 않는다. 경기 종료로60초를 관찰하지 못한 사례는 관찰 미완료로 분리한다.

각 패턴은 기회 수/발생 수/성공·실패·관찰 미완료, 관련 match_id/명령·이벤트 참조/시뮬레이션 시각을 보존한다. 설명용 대표 성공·실패 사례는 각각 최대3개로 제한하고 원본 대형 리플레이 누적은 추가하지 않는다.

### 2.3 발견의 증거 단계

- **자료 부족:** 이전 정책/조건/사건 정보 또는 표본이 부족하다.
- **관측된 변화:** 행동 선택률·순서·성과가 달라졌다. 향상이나 원인으로 부르지 않는다.
- **발견 후보:** 고정된 이전/새 정책의 동일 조건 개발 평가에서 변화가 반복되고 결과 개선도 관측됐다. 선택률 또는 패턴 성공률 변화10%p 이상, 비교 양쪽 관련 기회20회 이상을 최초 탐지 기준으로 사용한다. 다른 지표도 차트에는 남긴다.
- **지정 범위에서 재현된 개선:** 별도 확인 seed와 전술 개입 비교까지 통과했다. 일반적인 새 맵 전이나 새로운 전술의 발명을 뜻하지 않는다.
- **재현 실패/불리한 변화:** 확인 평가에서 이득이 사라지거나 손실/시간/자원 비용이 늘었다. 성공 보고서와 같이 보존한다.

보류 평가20경기는5개 seed의4조합으로 묶어서 다룬다.80경기를 독립 표본80개처럼 취급하지 않는다. 확인 평가의 불확실성은 seed 단위 paired bootstrap95% 구간으로 표시한다.

### 2.4 전술 개입 비교

250경기마다 탐지된 후보 중 개발 평가의 승리점수 차가 가장 큰 것 하나만 확인한다. 동률은 평균 게임 점수 차, 정책 세대 오름차순으로 정한다. 후보가 없으면 검증 경기를 억지로 만들지 않는다.

이전/새 정책과 상대 모델을 고정하고, 새 확인 seed20개×A/B×서/동4조합에서 다음 네 조건을 비교한다.

- 이전 정책 / 후보 전술 허용
- 이전 정책 / 후보 전술 제외
- 새 정책 / 후보 전술 허용
- 새 정책 / 후보 전술 제외

제외는 학습 팀의 해당 전술 행동 마스크에만 적용한다. 후보 ID·순서·관측 계약을 유지하고 대기 행동은 항상 남긴다. 상대·자원·맵·판정·초기 seed를 고정하고 학습 업데이트/교사 표본 수집/NIM 호출은 하지 않는다.

주 지표는 승리1·무승부0.5·패배0의 seed별 평균이다. 전체 새 정책의 개선과 전술 허용 효과의 증가가 모두 paired95% 구간에서 양수여야 '지정 범위에서 재현된 개선'으로 올린다. 점수 차·거점 유지·손실·보급 비용은 보조 지표와 손익으로 함께 표시한다. 개입은 전술의 사용 가능성을 바꾼 실험이므로 특정 명령 하나가 단독 원인이라고 확대 해석하지 않는다.

동일 정책/판정/평가 세트의 기존 결과는 해시로 확인해 재사용한다. 한 번에 확인 후보1개만 처리하고 대기열·진행률·완료 결과를 저장해 재개한다. 평가 작업은 CPU1개로 제한하고 활성 평가 중에는 학습도1개 thread로 제한해 두 작업 합계2개를 기본 예산으로 한다. 새 API 비용을 추가하지 않는다.

## 3. 보고서·사이트 인터페이스

- 정책별 변화 타임라인: 행동 지문, 선택 기회 대비 비중, 실제 완료율과 전투/점령/자원 성과를 같이 보여준다.
- 발견 카드: 무엇이 얼마나 달라졌는지, 이전/새 정책, 조건, 표본 수, 증거 단계, 검증 범위, 실패/반례, 정확한 정책 보존·다운로드 참조를 표시한다.
- 전후 비교: 같은 조건의 두 정책과 전술 허용/제외 결과를 표·간단한 차트로 비교한다. 학습 경기 추세와 고정 평가를 분리한다.
- 특정 시점의 요약(JSON/Markdown)을 불변 report_id로 보관한다. 원격 이관 인덱스에서 정책·통계·보고서 체크섬을 연결한다.
- 기존 통계 API와 별도로 읽기 전용 /api/insights와 /api/insights/{report_id}를 추가한다. 목록은 실행/규칙/정책/전술/증거 단계로 필터링하고 페이지당20개를 반환한다.
- 웹의 '전술 변화·발견' 화면은 최신 학습 경기에만 리플레이 연결을 제공한다. 과거 사례는 기록된 사건 시각과 통계로 표시한다.
- 설명은 검증된 수치와 고정 템플릿으로 작성한다. LLM에게 전략 이야기를 창작시키는 추가 호출을 하지 않는다.

표시 예: '방어 선택률22%→35%, 거점 유지+18%; 개발 평가에서는 개선됐으나 확인 평가 미완료 — 발견 후보.' 이 숫자는 표시 방식 예시이며 현재 학습의 실제 결과가 아니다.

## 4. 검증과 완료 기준

- 같은 기록을 두 번 집계해도 패턴·보고서·경기 수가 증가하지 않는다. checkpoint 중단 후 재개에서도 집계가 일치한다.
- 행동 빈도만 증가하고 승패 이득이 없는 fixture를 발견으로 승격하지 않는다.
- 후보 생성기/엔진/맵/상대/초기 조건이 바뀐 비교는 학습 단독 효과로 표시하지 않는다.
- 의도적으로 효과가 있는 스크립트 사례, 효과 없는 사례, 나쁜 변화, 관찰 미완료, 구형 정보 누락에서 증거 단계가 맞는다.
- 개입 마스크가 후보 ID를 바꾸거나 상대 정책/숨겨진 정보/게임 RNG를 변경하지 않는다. 같은 조건 재실행은 같은 해시를 얻는다.
- 정책·보고서·평가 결과 해시가 서로 맞고, 최고 평가 정책이 최신 checkpoint 정리로 삭제되지 않는다.
- 승률 향상 없이 지표 일부만 좋아진 경우와 새 맵 미검증 상태를 사이트에서도 정확히 표시한다.

구현 순서: 안전 보존→통계/아카이브→공정 배정/실행 병목→고정 평가→행동 지문/발견 후보→개입 확인/사이트. 각 단계는 테스트→STATE→커밋→push. 계획 저장은 구현 완료나 원격 모델 보존 성공을 의미하지 않는다.
