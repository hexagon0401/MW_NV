# C02–C21 구현 기록

## 검증 범위

작업카드의 단계별 완료 조건을 구현했다. 각 Cxx는 테스트 후 개별 커밋·push했다.
최종 검증은 단위·통합 테스트, 규칙 HQ 10경기, 별도 10 seed의 A/B 위치 교환 20경기다.
전체 v1.0.0 출시 완료나 Intel Mac 성능 검증을 뜻하지 않는다.

## 명세에서 비어 있던 세부 결정

- 명령 ID는 팀별 정수이고 저장소도 팀별로 분리한다. 외부 정책은 submit_for를 사용한다.
- 같은 유닛의 실행 가능한 명령 중 priority, tick, cmd_id가 큰 명령이 우선하며
  다른 명령을 취소한다. 미래 예약 명령은 실행 시각 이전에 현재 행동을 바꾸지 않는다.
- 0.5초 승하차는 0.2초 tick의 누적 타이머로 구현한다. 첫 탑승은 0.6초,
  두 번째는 1.0초로, 매번 0.6초씩 지연을 누적하지 않는다.
- 경합 중 점령은 일시 정지, 인원 미달은 초기화한다. 중립화 후 점령 타이머를 새로 시작한다.
- 30초 점수는 같은 tick의 모든 거점에 지급한 후 승리를 판정하므로 100점을 초과할 수 있다.
  Hot Zone은 첫 5분 중앙이며, 경계 tick의 득점까지 이전 Hot Zone을 적용한다.
- 45분 동점 시 5분 전체 연장을 실행한다(100점 선취는 연장 중에도 유효).
- 탄약/회복/연료 자원은 배치 단위 올림 과금한다. MED 8HP 회복은 공급 1과 heal_pool 8을 소모한다.
- 난수·상태·현재 명령·이벤트를 해시에 포함한다. 미래 LLM의 재생성 일치는 보장하지 않는다.
- 슬롯·데이터 설정 도입과 통합 연결은 파일 수 권장치를 넘긴 단계가 있다.
  기존 모듈 연결에 필요한 변경이며 별도 기능을 선행 구현하지 않았다.

## 남은 전체 명세 항목과 한계

- C21-L1/L2 실제 로컬 LLM 연동, C22 리플레이 적용, C23 1024m 맵·부하 측정,
  웹 관전·클라우드 연동·RL은 아직 구현하지 않았다.
- PURCHASE 실행, ENG 시설 작업, 점령 타워 시야 보너스는 후속 구현이 필요하다.
- 동적 길막힘은 BLOCKED로 반환한다. 국소 우회 한 번을 시도하는 개선은 아직 없다.
- 팀 관측/명령을 격리하지만 정책 코드를 별도 OS 프로세스로 샌드박싱한 것은 아니다.
- 규칙 HQ의 전술은 단순하다. 일부 seed는 인원 손실/경합으로 0:0 무승부가 된다.
  공격 대상은 ID 순서 기반으로 결정하며 실제 팀별 승률 균형은 후속 평가 대상이다.
- 경로 캐시·완료 명령·이벤트는 한 경기 동안 보존한다. 큰 맵/장시간 최적화는 C23 대상이다.
- 모델·가중치·서비스 키·유료 인프라를 추가하지 않았다. GitHub API는 Forbidden으로
  PR 조회가 차단되었다. Git HTTPS push는 성공하며 main 병합은 하지 않았다.
